## Inicio rápido

### Autenticación

Incluye tu clave de API en el encabezado `X-API-KEY`:

```bash
X-API-KEY: <api-key>
```

### Solicitud de ejemplo

```bash
curl --request POST \
  --url https://app.chainpatrol.io/api/v2/threats/list \
  --header 'Content-Type: application/json' \
  --header 'X-API-KEY: <api-key>' \
  --data '{
    "query": "phishing",
    "assetType": ["URL", "ADDRESS"],
    "startDate": "2024-01-01",
    "endDate": "2024-01-31",
    "per_page": 50,
    "sorting": [
      {
        "key": "blockedAt",
        "direction": "desc"
      }
    ]
  }'
```

## Esquema de la solicitud

### Cuerpo de la solicitud

| Campo       | Tipo              | Obligatorio | Valor predeterminado              | Restricciones      | Descripción                                                  |
| ----------- | ----------------- | ----------- | --------------------------------- | ------------------ | ------------------------------------------------------------ |
| `query`     | `string`          | ❌ No       | -                                 | -                  | Consulta de búsqueda para filtrar amenazas por contenido     |
| `startDate` | `string`          | ❌ No       | hace 1 día                        | Formato YYYY-MM-DD | Fecha de inicio para filtrar amenazas (inclusive)            |
| `endDate`   | `string`          | ❌ No       | ahora                             | Formato YYYY-MM-DD | Fecha de fin para filtrar amenazas (inclusive)               |
| `assetType` | `AssetType[]`     | ❌ No       | -                                 | -                  | Arreglo de tipos de **asset** (activo digital: URL, dirección, perfil, app, etc.) por los que filtrar |
| `sorting`   | `SortingConfig[]` | ❌ No       | `[{key: "id", direction: "asc"}]` | -                  | Arreglo de configuraciones de ordenamiento                   |
| `per_page`  | `number`          | ❌ No       | `10`                              | Mín.: 1, Máx.: 100 | Cantidad de amenazas que se devuelven por página             |
| `next_page` | `string`          | ❌ No       | -                                 | Valor de `next_page` en la respuesta anterior | Cursor para obtener la siguiente página de resultados        |
| `includePending` | `boolean`    | ❌ No       | `false`                           | -                  | Devuelve también los bloqueos pendientes (ver más abajo)     |

<Warning>
Sin `startDate` ni `endDate`, este endpoint devuelve solo las amenazas bloqueadas en
el **último día**. Ambas fechas filtran por `blockedAt`. Para listar todas las amenazas confirmadas,
envía un `startDate` antiguo, como `"2020-01-01"`.
</Warning>

### Bloqueos pendientes

Si la protección no está activa para tu organización, ChainPatrol igual revisa lo que
encuentra, pero las amenazas confirmadas quedan en espera como **Pending Blocked** en lugar de
aplicarse en la **Blocklist** (lista de bloqueo). De forma predeterminada se excluyen, porque este endpoint alimenta
a los consumidores de la Blocklist. Establece `includePending: true` para incluirlas. Se devuelven con
`pendingStatus: "BLOCKED"`, y su `blockedAt` indica cuándo se confirmó el bloqueo.

### Configuración de ordenamiento

Cada objeto de ordenamiento debe tener la siguiente estructura:

| Campo       | Tipo                | Obligatorio | Descripción                                             |
| ----------- | ------------------- | ----------- | ------------------------------------------------------- |
| `key`       | `string`            | ✅ Sí       | Campo por el que se ordena (ver las opciones más abajo) |
| `direction` | `"asc"` \| `"desc"` | ✅ Sí       | Dirección del ordenamiento                              |

#### Campos de ordenamiento disponibles

- `"id"` - Ordena por ID de la amenaza
- `"blockedAt"` - Ordena por el momento en que se bloqueó el asset
- `"content"` - Ordena por contenido de la amenaza
- `"type"` - Ordena por tipo de asset

## Esquema de la respuesta

### Cuerpo de la respuesta

```typescript
{
  threats: ThreatResult[];
  next_page: string | null;
}
```

### Objeto de resultado de amenaza

Cada elemento del arreglo `threats` tiene la siguiente estructura:

| Campo       | Tipo     | Descripción                                                    |
| ----------- | -------- | -------------------------------------------------------------- |
| `id`        | `number` | Identificador único de la amenaza                              |
| `content`   | `string` | Contenido de la amenaza (URL, dirección, nombre de usuario, etc.) |
| `type`      | `string` | Tipo de asset (valor del enum AssetType)                       |
| `blockedAt` | `string` | Marca de tiempo ISO 8601 del momento en que se bloqueó el asset |
| `pendingStatus` | `string \| null` | `"BLOCKED"` para un bloqueo pendiente (solo se devuelve con `includePending`); de lo contrario, `null` |

## Control de acceso

La API aplica un control de acceso estricto según tu clave de API:

1. **Claves de API de organización**:

   - Solo pueden acceder a las amenazas de su organización asociada
   - Devuelven solo las amenazas que fueron bloqueadas por la organización
   - Ejemplo: una clave de API de "acme-org" solo puede consultar las amenazas bloqueadas por "acme-org"

2. **Claves de API de usuario**:
   - Pueden acceder a las amenazas de cualquier organización de la que el usuario sea miembro
   - Requieren que el usuario sea un miembro activo de la organización consultada

Si intentas acceder a las amenazas sin los permisos adecuados, recibirás un error 401 Unauthorized con el mensaje: "Valid API key required"

## Comportamiento predeterminado

- **Rango de fechas**: Si no se proporciona `startDate` ni `endDate`, la API devuelve de forma predeterminada las amenazas del último día. Si solo se envía `startDate`, `endDate` toma como valor predeterminado el momento actual; si solo se envía `endDate`, `startDate` toma como valor predeterminado un día antes de esa fecha
- **Bloqueos pendientes**: Se excluyen a menos que `includePending` sea `true`
- **Paginación**: Si no se proporciona `next_page`, devuelve la primera página de resultados
- **Ordenamiento**: De forma predeterminada ordena por `id` en orden ascendente
- **Tamaño de página**: De forma predeterminada son 10 resultados por página (máx. 100)

## Implementación de ejemplo

<CodeGroup>

```javascript JavaScript
async function fetchThreats(params) {
  const response = await fetch("https://app.chainpatrol.io/api/v2/threats/list", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "X-API-KEY": "<api-key>",
    },
    body: JSON.stringify(params),
  });
  return response.json();
}

// Example usage
fetchThreats({
  query: "phishing",
  assetType: ["URL", "ADDRESS"],
  startDate: "2024-01-01",
  endDate: "2024-01-31",
  per_page: 50,
  sorting: [
    {
      key: "blockedAt",
      direction: "desc",
    },
  ],
})
  .then((data) => {
    console.log("Threats found:", data.threats.length);
    data.threats.forEach((threat) => {
      console.log(`ID: ${threat.id}`);
      console.log(`Content: ${threat.content}`);
      console.log(`Type: ${threat.type}`);
      console.log(`Blocked At: ${threat.blockedAt}`);
      console.log("---");
    });

    if (data.next_page) {
      console.log("More results available with next_page:", data.next_page);
    }
  })
  .catch((error) => console.error("Error fetching threats:", error));
```

```typescript TypeScript
interface SortingConfig {
  key: "id" | "blockedAt" | "content" | "type";
  direction: "asc" | "desc";
}

interface ThreatListParams {
  query?: string;
  startDate?: string;
  endDate?: string;
  assetType?: string[];
  sorting?: SortingConfig[];
  per_page?: number;
  next_page?: string;
  includePending?: boolean;
}

interface ThreatResult {
  id: number;
  content: string;
  type: string;
  blockedAt: string;
  pendingStatus: string | null;
}

interface ThreatListResponse {
  threats: ThreatResult[];
  next_page: string | null;
}

async function fetchThreats(
  params: ThreatListParams
): Promise<ThreatListResponse> {
  const response = await fetch("https://app.chainpatrol.io/api/v2/threats/list", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "X-API-KEY": "<api-key>",
    },
    body: JSON.stringify(params),
  });
  return response.json();
}

// Example usage with pagination
async function getAllThreats(params: ThreatListParams) {
  const allThreats: ThreatResult[] = [];
  let nextPage: string | null = null;

  do {
    const response = await fetchThreats({
      ...params,
      next_page: nextPage || undefined,
    });

    allThreats.push(...response.threats);
    nextPage = response.next_page;
  } while (nextPage);

  return allThreats;
}

// Get all URL threats from the first week of January 2024
getAllThreats({
  assetType: ["URL"],
  startDate: "2024-01-01",
  endDate: "2024-01-07",
  per_page: 100,
})
  .then((threats) => {
    console.log(`Found ${threats.length} URL threats in the first week of January 2024`);
  })
  .catch((error) => console.error("Error fetching all threats:", error));
```
