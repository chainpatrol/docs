## Descripción general

Lista las **Suspected Threats** (amenazas sospechosas detectadas automáticamente, todavía sin confirmar) de tu organización: **Assets** (activos digitales: URL, direcciones, perfiles, apps, etc.) que la detección
automatizada de ChainPatrol marcó. Una suspected threat no está confirmada hasta que se revisa y
se bloquea. Usa el filtro `blockStatus` que aparece más abajo para seleccionar las que ya fueron
confirmadas.

La API conserva el nombre "detection": el endpoint es `/detection/list`, los resultados vienen
en el arreglo `detections` y cada elemento es un resultado de detección.

## Inicio rápido

### Autenticación

Incluye tu clave de API en el encabezado `X-API-KEY`:

```bash
X-API-KEY: <api-key>
```

### Solicitud de ejemplo

```bash
curl --request POST \
  --url https://app.chainpatrol.io/api/v2/detection/list \
  --header 'Content-Type: application/json' \
  --header 'X-API-KEY: <api-key>' \
  --data '{
    "slug": "your-org",
    "limit": 50,
    "query": "phishing",
    "filters": [
      {
        "property": "source",
        "operator": "in",
        "value": ["EXTERNAL", "GOOGLE_SEARCH"]
      },
      {
        "property": "assetStatus",
        "operator": "in",
        "value": ["BLOCKED"]
      },
      {
        "property": "confidence",
        "operator": "in",
        "value": ["high", "medium"]
      }
    ]
  }'
```

## Esquema de la solicitud

### Cuerpo de la solicitud

| Campo       | Tipo       | Obligatorio | Valor predeterminado | Restricciones     | Descripción                                        |
| ----------- | ---------- | ----------- | -------------------- | ----------------- | -------------------------------------------------- |
| `slug`      | `string`   | ✅ Sí       | -                    | -                 | Identificador (slug) de la organización            |
| `cursor`    | `number`   | ❌ No       | -                    | -                 | `nextCursor` de la respuesta anterior              |
| `limit`     | `number`   | ❌ No       | `50`                 | Mín.: 1, Máx.: 1000 | Cantidad de resultados por página                |
| `filters`   | `Filter[]` | ❌ No       | `[]`                 | -                 | Arreglo de objetos de filtro                       |
| `query`     | `string`   | ❌ No       | `""`                 | -                 | Consulta de búsqueda sobre el contenido de la amenaza (no distingue mayúsculas de minúsculas) |
| `startDate` | `string`   | ❌ No       | -                    | Formato ISO 8601  | Solo las suspected threats creadas en este momento o después |
| `endDate`   | `string`   | ❌ No       | -                    | Formato ISO 8601  | Solo las suspected threats creadas en este momento o antes |
| `minScore`  | `number`   | ❌ No       | -                    | 0–1, inclusivo    | Solo las suspected threats cuyo `score` sin procesar es al menos este valor |
| `maxScore`  | `number`   | ❌ No       | -                    | 0–1, inclusivo    | Solo las suspected threats cuyo `score` sin procesar es como máximo este valor |
| `includeTotal` | `boolean` | ❌ No    | `false`              | -                 | Devuelve también `total`, la cantidad de coincidencias en todas las páginas |

<Warning>
`startDate` y `endDate` filtran según cuándo se creó la **suspected threat**, no
según cuándo el asset se vio por primera vez, se reportó o se bloqueó. Omite ambos cuando quieras
todas las suspected threats: un rango de fechas deja fuera en silencio el historial más antiguo, lo que se interpreta
como resultados faltantes y no como un filtro.
</Warning>

### Esquema del filtro

Cada objeto de filtro debe tener la siguiente estructura:

| Campo      | Tipo       | Obligatorio | Descripción                                        |
| ---------- | ---------- | ----------- | -------------------------------------------------- |
| `property` | `string`   | ✅ Sí       | Propiedad del filtro (consulta las opciones más abajo) |
| `operator` | `string`   | ✅ Sí       | `"in"` o `"notIn"`                                 |
| `value`    | `string[]` | ✅ Sí       | Arreglo de valores por los que se filtra           |

**2. Filtro de estado del asset (`"assetStatus"`)**

```typescript
{
  "property": "assetStatus",
  "operator": "in" | "notIn",
  "value": AssetStatus[]
}
```

**Valores de estado del asset disponibles:**

- `"UNKNOWN"` - Estado aún no determinado
- `"ALLOWED"` - El asset es legítimo/está permitido
- `"BLOCKED"` - El asset está bloqueado/es malicioso

**3. Filtro de confianza (`"confidence"`)**

```typescript
{
  "property": "confidence",
  "operator": "in" | "notIn",
  "value": ConfidenceLevel[]
}
```

**Valores de nivel de confianza disponibles:**

- `"none"` - No se alcanzó ningún umbral de confianza
- `"low"` - Suspected threat de confianza baja
- `"medium"` - Suspected threat de confianza media
- `"high"` - Suspected threat de confianza alta

**4. Filtro de estado de bloqueo (`"blockStatus"`)**

```typescript
{
  "property": "blockStatus",
  "operator": "in" | "notIn",
  "value": ("blocked" | "pending")[]
}
```

Selecciona las suspected threats cuyo asset ya se convirtió en una **amenaza confirmada**:

- `"blocked"` - el asset está en la **Blocklist** (lista de bloqueo) (`asset.status` es `"BLOCKED"`)
- `"pending"` - se confirmó que el asset es malicioso, pero todavía no se aplica el bloqueo
  porque la protección no está activa para tu organización
  (`asset.pendingStatus` es `"BLOCKED"`). La app de ChainPatrol las etiqueta como
  **Pending Blocked** (bloqueo pendiente).

Pasa ambos valores para obtener todas las amenazas confirmadas, tal como las cuenta la app. El
filtro `assetStatus` solo ve `asset.status`, así que `assetStatus: ["BLOCKED"]`
deja fuera los bloqueos pendientes.

**5. Filtro de eliminadas (`"deleted"`)**

```typescript
{
  "property": "deleted",
  "operator": "in" | "notIn",
  "value": ["deleted"]
}
```

Las suspected threats eliminadas se **incluyen de forma predeterminada**. Agrega
`{ "property": "deleted", "operator": "notIn", "value": ["deleted"] }` para dejarlas
fuera, o usa `"in"` para devolver solo las eliminadas.

**6. Filtro de tipo de asset (`"assetType"`)**

```typescript
{
  "property": "assetType",
  "operator": "in" | "notIn",
  "value": AssetType[]
}
```

## Esquema de la respuesta

### Cuerpo de la respuesta

```typescript
{
  detections: DetectionResult[];
  nextCursor?: number; // omitted on the last page
  total?: number; // only when includeTotal is true
}
```

### Objeto de resultado de detección

Cada elemento del arreglo `detections` es una suspected threat, con la siguiente
estructura:

| Campo           | Tipo          | Descripción                                               |
| --------------- | ------------- | --------------------------------------------------------- |
| `id`            | `number`      | Identificador único del resultado de detección de amenazas |
| `threatContent` | `string`      | Contenido que se detectó como amenaza                     |
| `source`        | `string`      | Fuente de detección que lo encontró (ThreatDetectionSourceKey) |
| `createdAt`     | `string`      | Marca de tiempo ISO 8601 del momento en que se detectó    |
| `confidence`    | `string`      | Nivel de confianza: `"none"`, `"low"`, `"medium"` o `"high"` |
| `score`         | `number`      | Puntaje sin procesar del modelo (0–1) a partir del cual se agrupa `confidence` |
| `reportStatus`  | `string`      | Estado del reporte: `"REPORTED"` o `"NOT_REPORTED"`       |
| `asset`         | `AssetObject` | Información del asset asociado                            |

### Objeto de asset

| Campo     | Tipo     | Descripción                                   |
| --------- | -------- | --------------------------------------------- |
| `id`      | `number` | Identificador único del asset                 |
| `content` | `string` | Contenido del asset (URL, dirección, nombre de usuario, etc.) |
| `type`    | `string` | Tipo de asset (valor del enum AssetType)      |
| `status`  | `string` | Estado actual del asset (valor del enum AssetStatus) |
| `pendingStatus` | `string \| null` | Un estado ya revisado que todavía no entró en vigor. `"BLOCKED"` significa que se confirmó como malicioso, pero no se aplica porque la protección no está activa ("Pending Blocked"). `null` cuando no hay nada pendiente. |

## Conteos y umbrales de puntaje

Para contar las suspected threats sin tener que paginarlas, envía `includeTotal: true`.
La respuesta incluye entonces `total`: cuántas suspected threats coinciden con tus filtros,
tu búsqueda y tu rango de fechas en todas las páginas. Se cuenta antes de aplicar el cursor, así que cada
página de un recorrido informa el mismo número. Implica una consulta de conteo adicional, así que pídelo
en la primera página y no en todas.

`confidence` se agrupa a partir de `score` según los umbrales propios de tu organización, así que
`"high"` no equivale a un puntaje fijo. Para un umbral fijo, como "más del 80%", usa
`minScore` (y, si quieres, `maxScore`):

```bash
curl --request POST \
  --url https://app.chainpatrol.io/api/v2/detection/list \
  --header 'Content-Type: application/json' \
  --header 'X-API-KEY: <api-key>' \
  --data '{
    "slug": "your-org",
    "limit": 10,
    "minScore": 0.8,
    "includeTotal": true,
    "filters": [
      { "property": "deleted", "operator": "notIn", "value": ["deleted"] }
    ]
  }'
```

Un `minScore` mayor que `maxScore` se rechaza con un `400`.

Consulta [Cómo evaluar las suspected threats](/es/external-api/evaluating-detections) para ver las
preguntas que suele hacerse la gente cuando mira estos datos por primera vez, y la solicitud
que responde cada una.

## Paginación y sincronización incremental

Las suspected threats se devuelven de la más reciente a la más antigua. No hay una exportación en una sola llamada: una
organización puede tener cientos de miles de suspected threats, muchas más de las que caben
en una respuesta. En su lugar, recórrelas por páginas:

- Establece `limit` en hasta **1000**.
- Pasa el `nextCursor` de cada respuesta como `cursor`.
- Detente cuando una respuesta no tenga `nextCursor`.

<Note>
Las respuestas tienen un tope de 4MB. Una página que lo supere falla con un error `413`
en lugar de recortarse. Reintenta con un `limit` más pequeño. Una página de 1000 filas
suele quedar muy por debajo de 1MB.
</Note>

### Obtener solo las suspected threats nuevas

Después de una sincronización completa inicial, usa `startDate` para que cada ejecución solo obtenga lo que se
creó desde la anterior. Con 1,000 a 10,000 suspected threats nuevas por día, eso
equivale a unas pocas páginas de 1000 filas.

1. Registra la hora en que empieza la sincronización y envíala como `endDate`. Las suspected threats
   creadas mientras estás paginando quedan al frente del orden (de la más reciente a la más antigua), así que sin
   un `endDate` fijo se omitirían. En cambio, las toma la siguiente ejecución.
2. Establece `startDate` en la hora de inicio de la ejecución anterior, menos unos minutos de
   superposición. Una suspected threat puede tardar unos segundos en ser visible después de su
   `createdAt`, y la superposición la captura.
3. Pagina hasta que no haya `nextCursor` y elimina los duplicados por `id`. La superposición
   hace que algunas suspected threats aparezcan en dos ejecuciones.

Las suspected threats eliminadas se incluyen a menos que agregues
`{ "property": "deleted", "operator": "notIn", "value": ["deleted"] }` a
`filters`. Para obtener solo los dominios falsos sospechosos, agrega
`{ "property": "assetType", "operator": "in", "value": ["URL"] }`.

<Warning>
Una sincronización con `startDate` solo devuelve las suspected threats *creadas* dentro del rango. Si una
suspected threat se reporta o se elimina después de que la obtuviste, la siguiente ejecución incremental
no la volverá a devolver. Ejecuta una sincronización completa periódica (por ejemplo, diaria) si
necesitas esos cambios.
</Warning>

```javascript JavaScript
async function fetchDetections({ slug, startDate, endDate, filters = [] }) {
  const detections = new Map();
  let cursor;

  do {
    const response = await fetch("https://app.chainpatrol.io/api/v2/detection/list", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "X-API-KEY": "<api-key>",
      },
      body: JSON.stringify({
        slug,
        limit: 1000,
        filters,
        ...(startDate ? { startDate } : {}),
        ...(endDate ? { endDate } : {}),
        ...(cursor ? { cursor } : {}),
      }),
    });
    if (!response.ok) {
      throw new Error(`detection/list failed: ${response.status}`);
    }
    const data = await response.json();
    for (const detection of data.detections) {
      detections.set(detection.id, detection);
    }
    cursor = data.nextCursor;
  } while (cursor);

  return [...detections.values()];
}

// Incremental run: everything created since the previous run started.
const OVERLAP_MS = 5 * 60 * 1000;
const syncStartedAt = new Date();
const previousSyncStartedAt = new Date("2026-09-24T00:00:00Z"); // load from your store

const newDetections = await fetchDetections({
  slug: "your-org",
  startDate: new Date(previousSyncStartedAt.getTime() - OVERLAP_MS).toISOString(),
  endDate: syncStartedAt.toISOString(),
  filters: [{ property: "assetType", operator: "in", value: ["URL"] }],
});
// Save `syncStartedAt` as the next run's `previousSyncStartedAt`.
```

```python Python
from datetime import datetime, timedelta, timezone

import requests

def fetch_detections(slug, start_date=None, end_date=None, filters=None):
    detections = {}
    cursor = None
    while True:
        body = {"slug": slug, "limit": 1000, "filters": filters or []}
        if start_date:
            body["startDate"] = start_date.isoformat()
        if end_date:
            body["endDate"] = end_date.isoformat()
        if cursor:
            body["cursor"] = cursor
        response = requests.post(
            "https://app.chainpatrol.io/api/v2/detection/list",
            headers={"Content-Type": "application/json", "X-API-KEY": "<api-key>"},
            json=body,
        )
        response.raise_for_status()
        data = response.json()
        for detection in data["detections"]:
            detections[detection["id"]] = detection
        cursor = data.get("nextCursor")
        if not cursor:
            break
    return list(detections.values())

# Incremental run: everything created since the previous run started.
sync_started_at = datetime.now(timezone.utc)
previous_sync_started_at = datetime(2026, 9, 24, tzinfo=timezone.utc)  # load from your store

new_detections = fetch_detections(
    "your-org",
    start_date=previous_sync_started_at - timedelta(minutes=5),
    end_date=sync_started_at,
    filters=[{"property": "assetType", "operator": "in", "value": ["URL"]}],
)
# Save `sync_started_at` as the next run's `previous_sync_started_at`.
```

## Control de acceso

La API aplica un control de acceso estricto según tu clave de API:

1. **Claves de API de organización**:

   - Solo pueden acceder a las suspected threats de la organización a la que están asociadas
   - Deben coincidir exactamente con el parámetro `slug`
   - Ejemplo: una clave de API de "acme-org" solo puede consultar resultados de "acme-org"

2. **Claves de API de usuario**:
   - Pueden acceder a las suspected threats de cualquier organización de la que el usuario sea miembro
   - Requieren que el usuario sea un miembro activo de la organización consultada

Si intentas consultar una organización sin los permisos adecuados, recibirás un error 403 Forbidden con el mensaje: "API key does not have access to this organization"

```typescript TypeScript
interface DetectionFilter {
  property:
    | "source"
    | "assetStatus"
    | "blockStatus"
    | "deleted"
    | "assetType"
    | "confidence";
  operator: "in" | "notIn";
  value: string[];
}

interface DetectionListParams {
  slug: string;
  cursor?: number;
  limit?: number;
  filters?: DetectionFilter[];
  query?: string;
  startDate?: string;
  endDate?: string;
  minScore?: number;
  maxScore?: number;
  includeTotal?: boolean;
}

interface AssetObject {
  id: number;
  content: string;
  type: string;
  status: string;
  pendingStatus: string | null;
}

interface DetectionResult {
  id: number;
  threatContent: string;
  source: string;
  createdAt: string;
  confidence: "none" | "low" | "medium" | "high";
  score: number;
  reportStatus: "REPORTED" | "NOT_REPORTED";
  asset: AssetObject;
}

interface DetectionListResponse {
  detections: DetectionResult[];
  nextCursor?: number;
  total?: number;
}

async function fetchDetectionResults(
  params: DetectionListParams
): Promise<DetectionListResponse> {
  const response = await fetch("https://app.chainpatrol.io/api/v2/detection/list", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "X-API-KEY": "<api-key>",
    },
    body: JSON.stringify(params),
  });
  return response.json();
}
```
