## Descripción general

Obtén los reportes de seguridad de tu organización. Este endpoint devuelve todos los reportes enviados para tu organización, con detalles sobre los **Assets** (activos digitales: URL, direcciones, perfiles, apps, etc.) reportados, las **Proposals** (propuestas para bloquear o permitir un asset) y su estado actual. La organización se infiere automáticamente a partir de tu clave de API.

## Inicio rápido

### Autenticación

Incluye tu clave de API en el encabezado `X-API-KEY`:

```bash
X-API-KEY: your_api_key_here
```

## Parámetros de consulta

| Parámetro    | Tipo    | Obligatorio | Descripción                                                                                        |
| ------------ | ------- | ----------- | -------------------------------------------------------------------------------------------------- |
| limit        | number  | No          | Cantidad de reportes que se devuelven por página (1-100, valor predeterminado: 50)                 |
| cursor       | string  | No          | Cursor para la paginación. Pasa el cursor de la respuesta anterior para obtener la página siguiente. |
| startDate    | string  | No          | Filtra los reportes creados después de esta fecha (formato ISO 8601)                               |
| endDate      | string  | No          | Filtra los reportes creados antes de esta fecha (formato ISO 8601)                                 |
| onlyRejected | boolean | No          | Si es true, solo devuelve los reportes con Proposals rechazadas (valor predeterminado: false)      |
| needsCustomerReview | boolean | No | Si es true, solo devuelve los reportes que tienen al menos una Proposal a la espera de **tu** revisión: la misma cola que muestra tu página **Review** (revisión de propuestas pendientes de aprobación). Úsalo para responder "¿qué está esperando por mí?" y luego actúa sobre las Proposals con [`POST /organization/proposals/{proposalId}/review`](/es/external-api/organization-proposals-review). |

### Campos de la respuesta

| Campo                      | Tipo   | Descripción                                                              |
| -------------------------- | ------ | ------------------------------------------------------------------------ |
| reports                    | array  | Arreglo de objetos de reporte de tu organización                         |
| reports[].id               | string | Identificador único del reporte                                          |
| reports[].createdAt        | string | Marca de tiempo ISO 8601 del momento en que se creó el reporte           |
| reports[].status           | string | Estado general del reporte (`PENDING`, `APPROVED`, `REJECTED`)                 |
| reports[].assets           | array  | Arreglo de assets incluidos en el reporte                                |
| reports[].proposals        | array  | Arreglo de Proposals asociadas al reporte                                |
| reports[].proposals[].id   | number | Identificador único de la Proposal. Pásalo a [`POST /organization/proposals/{proposalId}/review`](/es/external-api/organization-proposals-review) para aprobar la Proposal, rechazarla o enviarla a la **Watchlist** (lista de seguimiento de assets sospechosos que se siguen monitoreando). |
| reports[].proposals[].reviewStatus | string | Estado de revisión de la Proposal (`PENDING`, `APPROVED`, `REJECTED`)  |
| reports[].proposals[].asset | object | El asset al que apunta la Proposal. Su `id` es el `assetId` que requiere el endpoint de revisión. |
| cursor                     | string | Cursor para la página siguiente de resultados (undefined si no hay más resultados) |

## Paginación

Usa la paginación basada en cursor para obtener todos los reportes:

<CodeGroup>

```typescript TypeScript
async function fetchAllReports() {
  let allReports = [];
  let cursor: string | undefined = undefined;

  while (true) {
    const params = new URLSearchParams({
      limit: "100",
      ...(cursor && { cursor }),
    });

    const response = await fetch(
      `https://app.chainpatrol.io/api/v2/organization/reports?${params}`,
      {
        method: "GET",
        headers: {
          "X-API-KEY": "YOUR_API_KEY_HERE",
        },
      }
    );

    const data = await response.json();
    allReports = allReports.concat(data.reports);
    cursor = data.cursor;

    if (!cursor) {
      break;
    }
  }

  return allReports;
}

fetchAllReports()
  .then((reports) => console.log(`Total reports: ${reports.length}`))
  .catch((error) => console.error("Error:", error));
```

```python Python
import requests

def fetch_all_reports():
    all_reports = []
    cursor = None

    while True:
        params = {"limit": 100}
        if cursor:
            params["cursor"] = cursor

        response = requests.get(
            "https://app.chainpatrol.io/api/v2/organization/reports",
            headers={"X-API-KEY": "YOUR_API_KEY_HERE"},
            params=params,
        )

        data = response.json()
        all_reports.extend(data["reports"])
        cursor = data.get("cursor")

        if not cursor:
            break

    return all_reports

try:
    reports = fetch_all_reports()
    print(f"Total reports: {len(reports)}")
except Exception as error:
    print(f"Error: {str(error)}")
```

## Ejemplos de filtros

### Filtrar por rango de fechas

Obtén los reportes de un período específico:

```bash
curl -X GET 'https://app.chainpatrol.io/api/v2/organization/reports?startDate=2024-01-01T00:00:00Z&endDate=2024-03-31T23:59:59Z' \
  -H 'X-API-KEY: YOUR_API_KEY_HERE'
```

### Filtrar solo los reportes rechazados

Obtén los reportes que tienen Proposals rechazadas:

```bash
curl -X GET 'https://app.chainpatrol.io/api/v2/organization/reports?onlyRejected=true' \
  -H 'X-API-KEY: YOUR_API_KEY_HERE'
```

### Filtrar los reportes que esperan tu revisión

Obtén los reportes que tienen al menos una Proposal a la espera de tu organización: la misma cola que muestra tu página Review:

```bash
curl -X GET 'https://app.chainpatrol.io/api/v2/organization/reports?needsCustomerReview=true&limit=20' \
  -H 'X-API-KEY: YOUR_API_KEY_HERE'
```

Cada reporte devuelto trae en `proposals[]` las Proposals sobre las que hay que actuar. Toma de ahí `proposals[].id` y `proposals[].asset.id` y pasa ambos a [`POST /organization/proposals/{proposalId}/review`](/es/external-api/organization-proposals-review).

### Combinar filtros

Obtén los reportes rechazados de un rango de fechas específico:

```bash
curl -X GET 'https://app.chainpatrol.io/api/v2/organization/reports?startDate=2024-01-01T00:00:00Z&endDate=2024-03-31T23:59:59Z&onlyRejected=true&limit=100' \
  -H 'X-API-KEY: YOUR_API_KEY_HERE'
```

## Respuestas de error

### 401 Unauthorized

Se devuelve cuando la clave de API falta, no es válida o no tiene acceso a la organización:

```json
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "API key with organization access required"
  }
}
```

### 400 Bad Request

Se devuelve cuando los parámetros de consulta no son válidos:

```json
{
  "error": {
    "code": "BAD_REQUEST",
    "message": "Invalid date format. Use ISO 8601 format."
  }
}
```

### Monitorear los reportes recientes

```typescript
async function getRecentReports(days: number = 7) {
  const startDate = new Date();
  startDate.setDate(startDate.getDate() - days);
```

### Dar seguimiento a los reportes rechazados

```typescript
async function analyzeRejectedReports() {
  const response = await fetch(
    "https://app.chainpatrol.io/api/v2/organization/reports?onlyRejected=true",
    {
      headers: { "X-API-KEY": "YOUR_API_KEY_HERE" },
    }
  );

  const { reports } = await response.json();

  // Analyze rejection reasons
  const rejectionReasons = reports.flatMap((report) =>
    report.proposals
      .filter((p) => p.status === "REJECTED")
      .map((p) => p.rejectionReason)
  );

  console.log("Common rejection reasons:", rejectionReasons);
  return rejectionReasons;
}
```

### Exportar reportes a CSV

```typescript
async function exportReportsToCSV(startDate: string, endDate: string) {
  const response = await fetch(
    `https://app.chainpatrol.io/api/v2/organization/reports?startDate=${startDate}&endDate=${endDate}&limit=100`,
    {
      headers: { "X-API-KEY": "YOUR_API_KEY_HERE" },
    }
  );

  const { reports } = await response.json();

  const csvHeader = "Report ID,Created At,Status,Assets,Proposals\n";
  const csvRows = reports
    .map(
      (r) =>
        `${r.id},${r.createdAt},${r.status},${r.assets.length},${r.proposals.length}`
    )
    .join("\n");

  const csv = csvHeader + csvRows;

  // Save or return CSV
  return csv;
}
```

## Buenas prácticas

### Paginación
- Usa `limit=100` para obtener datos en bloque y reducir al mínimo las llamadas a la API
- Revisa siempre el campo `cursor` para saber si hay más resultados
- Guarda el cursor si necesitas retomar la paginación más adelante

### Filtros por fecha
- Usa siempre el formato ISO 8601 para las fechas: `YYYY-MM-DDTHH:mm:ss.sssZ`
- Incluye la información de la zona horaria (normalmente UTC con el sufijo `Z`)
- Usa `startDate` y `endDate` juntos para definir rangos de tiempo precisos

### Rendimiento
- Guarda en caché los datos de los reportes cuando corresponda para reducir las llamadas a la API
- Usa filtros de fecha para limitar el tamaño del conjunto de resultados
- Si monitoreas la llegada de reportes nuevos, define intervalos de consulta periódica (se recomiendan de 5 a 10 minutos)

## Notas

- La organización se determina automáticamente a partir de tu clave de API
- Todas las marcas de tiempo están en formato ISO 8601 con zona horaria UTC
- El filtro `onlyRejected` muestra los reportes que tienen al menos una Proposal rechazada, pero el reporte puede contener otras Proposals aprobadas
- Los reportes se ordenan por fecha de creación (los más recientes primero)
- El cursor es opaco y no se debe analizar ni modificar
