## Descripción general

Lista todos los **assets** (activos digitales: URL, direcciones, perfiles, apps, etc.) reportados para tu organización, ya sea por tu equipo o por ChainPatrol, junto con
el estado en que se encuentra cada uno: todavía en investigación, escalado a ti, bloqueado o
permitido, y qué tan avanzado va su **takedown** (solicitud de baja de contenido fraudulento).

Úsalo para mantener una plataforma de inteligencia de amenazas, un SIEM o un sistema de tickets sincronizado con
ChainPatrol. Recórrelo página por página una vez para hacer la carga inicial (backfill); después consulta periódicamente con `updatedSince` y
haz un upsert de cada fila usando `id`.

Para listar solo las amenazas confirmadas que se bloquearon en un rango de fechas, usa
[`/threats/list`](/es/external-api/threats-list). Para listar las detecciones sin confirmar, usa
[`/detection/list`](/es/external-api/detection-list).

## Inicio rápido

### Autenticación

Incluye tu clave de API en el encabezado `X-API-KEY`. Las claves de API de organización determinan la
organización a partir de la clave, así que `slug` es opcional para ellas.

```bash
X-API-KEY: <api-key>
```

### Solicitud de ejemplo

```bash
curl --request GET \
  --url 'https://app.chainpatrol.io/api/v2/organization/threats?updatedSince=2026-11-01T00:00:00Z&per_page=500' \
  --header 'X-API-KEY: <api-key>'
```

## Parámetros de consulta

| Parámetro      | Tipo        | Obligatorio | Valor predeterminado | Descripción                                                                                                                                  |
| -------------- | ----------- | ----------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `slug`         | `string`    | ❌ No       | -                    | Slug de la organización. Solo se necesita cuando tus credenciales tienen acceso a más de una organización.                                   |
| `updatedSince` | `string`    | ❌ No       | -                    | Marca de tiempo ISO 8601. Solo las amenazas cuyo asset, reportes o takedown cambiaron en ese momento o después. Omítelo para la carga inicial (backfill). |
| `assetType`    | `AssetType` | ❌ No       | -                    | Solo las amenazas de este tipo de asset.                                                                                                     |
| `per_page`     | `number`    | ❌ No       | `100`                | Amenazas por página, de 1 a 1000.                                                                                                            |
| `next_page`    | `string`    | ❌ No       | -                    | El valor de `next_page` de la respuesta anterior.                                                                                            |

## Estados del ciclo de vida

`state` resume los reportes de cada asset y la decisión que se tomó sobre él:

| `state`         | Significado                                                                |
| --------------- | -------------------------------------------------------------------------- |
| `investigating` | Hay un reporte abierto y ChainPatrol lo está revisando.                    |
| `escalated`     | Hay un reporte abierto y está a la espera de una decisión de tu organización. |
| `blocked`       | El asset está en la **Blocklist** (lista de bloqueo).                      |
| `allowed`       | El asset está en la **Allowlist** (lista de permitidos).                   |
| `closed`        | Se revisaron todos los reportes y no se bloqueó nada.                      |

Una decisión sobre el asset prevalece sobre los reportes abiertos: una vez que está bloqueado o permitido,
`state` se queda ahí aunque alguien lo vuelva a reportar. Un asset que fue escalado,
decidido y luego reportado otra vez vuelve a `investigating`.

Las marcas de tiempo de cada amenaza:

- `firstReportedAt`: el primer reporte para tu organización.
- `escalatedAt`: la primera vez que el asset se escaló a tu organización, o
  `null` si nunca se escaló.
- `blockedAt`: cuándo se bloqueó el asset, o `null`.
- `takedown`: `null` hasta que se abre un takedown. `submittedAt` es la primera vez que
  se presentó ante un proveedor, y `completedAt` la primera vez que se completó. Si
  el sitio vuelve a aparecer, el takedown se reabre: `status` vuelve a `IN_PROGRESS` mientras que
  `completedAt` conserva la primera finalización. Vigila `status` para detectar reapariciones.
- `updatedAt`: el cambio más reciente en el asset, sus reportes o su takedown. Este es
  el valor contra el que se compara `updatedSince`.

## Consultar cambios periódicamente

1. **Carga inicial (backfill).** Llama sin `updatedSince` y sigue `next_page` hasta que sea
   `null`. Anota la hora en que empezaste.
2. **Consulta periódica (polling).** Envía `updatedSince` con un valor unos minutos anterior al inicio de tu última
   sincronización exitosa, y sigue `next_page` hasta que sea `null`, manteniendo el mismo
   `updatedSince` en cada página. Haz un upsert de cada amenaza usando `id`.
3. **Avanza.** Usa la hora de inicio de esta sincronización como marca de referencia (watermark) para la siguiente.

<Warning>
  Superpón tus ventanas de tiempo por unos minutos. De lo contrario, un cambio escrito mientras se ejecuta una solicitud
  puede quedar entre dos consultas. La superposición vuelve a enviar algunas amenazas que
  ya tienes, algo que un upsert absorbe.
</Warning>

Las páginas se ordenan por el `id` del asset, de forma ascendente, y el cursor es el último `id` devuelto,
así que los assets reportados a mitad de la sincronización quedan en páginas posteriores en lugar de desplazar las anteriores. Una
página puede contener menos amenazas que `per_page` mientras `next_page` todavía tiene un valor; continúa
hasta que `next_page` sea `null`.

```javascript
async function syncThreats(apiKey, updatedSince) {
  const threats = [];
  let nextPage = null;

  do {
    const params = new URLSearchParams({ per_page: "1000" });
    if (updatedSince) params.set("updatedSince", updatedSince);
    if (nextPage) params.set("next_page", nextPage);

    const response = await fetch(
      `https://app.chainpatrol.io/api/v2/organization/threats?${params}`,
      { headers: { "X-API-KEY": apiKey } },
    );
    if (!response.ok) throw new Error(`HTTP ${response.status}`);

    const page = await response.json();
    threats.push(...page.threats);
    nextPage = page.next_page;
  } while (nextPage);

  return threats;
}
```
