## Descripción general

El endpoint Crear reporte te permite enviar **Assets** (activos digitales: URL, dominios, direcciones de blockchain, etc.) para que el equipo de ChainPatrol los revise. Este endpoint admite envíos masivos y ofrece información detallada de los errores cuando falla la validación.

¿Es tu primera vez con este endpoint? Empieza por [Cómo crear reportes](/es/external-api/creating-reports): una
guía paso a paso de todo el flujo, con ejemplos prácticos.

<Note>
  Este endpoint necesita una clave de API con permiso **Read & write** (lectura y escritura). Una
  clave de solo lectura recibe `403 Forbidden`. Consulta [Permisos de la clave](/es/external-api/authentication#permisos-de-la-clave).
</Note>

## Adjuntos

`attachmentUrls` acepta URL de cualquier archivo de evidencia, no solo imágenes: los mensajes
`.eml` y `.msg`, los PDF, los documentos y las capturas de pantalla funcionan. Las imágenes se
muestran integradas en el reporte; los demás archivos se listan como evidencia descargable que
nuestro equipo de **Takedowns** (solicitudes de baja de contenido fraudulento) puede reenviar a
un registrador o proveedor de hosting.

Para enviarnos el archivo en sí en lugar de un enlace que tú alojas, súbelo primero con
[Subir archivo adjunto](/es/external-api/attachment-upload) y pasa la URL que devuelve:

```bash
# 1. upload the file, get a URL back
curl -X POST 'https://app.chainpatrol.io/api/v2/attachment/upload?fileName=evidence.eml' \
  -H 'X-API-KEY: YOUR_API_KEY_HERE' \
  --data-binary '@evidence.eml'

# 2. reference that URL here, in attachmentUrls
```

Los adjuntos pertenecen al reporte en su conjunto y no a un asset individual.

## Respuestas de error

### 422 Unprocessable Content

Se devuelve cuando la solicitud es sintácticamente válida pero contiene errores de validación o assets duplicados. Es el tipo de error más común y ofrece información detallada de errores por asset.

| Tipo de error            | Descripción                                                                                                              | Solución                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| `DUPLICATE_ASSETS`       | El mismo asset aparece varias veces en el reporte                                                                        | Quita los assets duplicados del envío                                 |
| `INVALID_FORMAT`         | El formato del asset no es válido                                                                                        | Usa URL, dominios o direcciones de blockchain válidos                 |
| `ASSET_NOT_FOUND`        | No se pudo ubicar ni crear el asset                                                                                      | Verifica el formato del asset y que sea accesible                     |
| `ASSET_ALREADY_CORRECT`  | El asset ya tiene el estado solicitado                                                                                   | No hace falta ninguna acción: el asset ya está en el estado deseado   |
| `ALREADY_PENDING_REVIEW` | El asset tiene una **Proposal** (propuesta para bloquear o permitir un asset) pendiente para el estado solicitado        | Espera a que se procese la Proposal existente                         |
| `REPORT_ALREADY_EXISTS`  | Ya existe un reporte o una Proposal pendiente para este asset                                                            | Revisa los reportes existentes o espera a que se procese              |
| `PROCESSING_FAILED`      | Ocurrió un error técnico durante el procesamiento del asset                                                              | Reintenta la solicitud o contacta a soporte                           |
| `DOMAIN_NOT_ALLOWED`     | El dominio del asset está en la lista de ignorados                                                                       | El dominio está excluido de los reportes según la política de contenido |
| `VALIDATION_ERROR`       | Error de validación genérico                                                                                             | Revisa el formato y los requisitos del asset                          |

#### Ejemplo: assets duplicados

```json
{
  "message": "Report creation failed: Duplicate assets found. 2 asset(s) appear multiple times in the same report.",
  "code": "UNPROCESSABLE_CONTENT",
  "data": {
    "errors": [
      {
        "asset": "scam.example",
        "errorType": "DUPLICATE_ASSETS",
        "message": "This asset appears multiple times in the same report",
        "suggestion": "Remove duplicate assets from your submission - each asset should only appear once per report"
      }
    ]
  }
}
```

#### Ejemplo: varios errores de validación

```json
{
  "message": "Report creation failed: 2 of 3 assets are invalid. All assets must be valid to create a report.",
  "code": "UNPROCESSABLE_CONTENT",
  "data": {
    "errors": [
      {
        "asset": "http",
        "errorType": "INVALID_FORMAT",
        "message": "This asset couldn't be processed due to invalid format",
        "suggestion": "Use valid URLs (https://example.com), domains (example.com), or blockchain addresses (eip155:1:0x123...)"
      },
      {
        "asset": "decen-masters.com",
        "errorType": "DOMAIN_NOT_ALLOWED",
        "message": "This domain cannot be reported as it's on the ignore list",
        "suggestion": "This domain is currently excluded from reports based on our content policy. Please reach out to us if you believe this is an error"
      }
    ]
  }
}
```

### 500 Internal Server Error

Se devuelve ante condiciones inesperadas del servidor, incluidos errores de base de datos y otras fallas técnicas. La respuesta usa mensajes seguros y genéricos para no exponer detalles internos del sistema.

#### Respuesta de error estándar

```json
{
  "message": "Unable to process your report. Please try again or contact support if the issue persists.",
  "code": "INTERNAL_SERVER_ERROR"
}
```

#### Respuesta de error de base de datos

```json
{
  "message": "A database error occurred. This has been reported internally - please contact support@chainpatrol.io for assistance.",
  "code": "INTERNAL_SERVER_ERROR"
}
```

## Buenas prácticas

### Validación de assets

**URL**: Incluye el protocolo completo (`https://` o `http://`)

**Dominios**: Usa nombres de dominio limpios, sin protocolos ni rutas

**Direcciones de blockchain**: Usa el formato EIP-155 para las direcciones de Ethereum

**Evita duplicados**: Cada asset debe aparecer una sola vez por reporte

### Manejo de errores

Revisa siempre el arreglo `data.errors` en las respuestas 422 para ver los detalles por asset

Usa el campo `suggestion` de las respuestas de error para orientar a los usuarios

Implementa una lógica de reintentos con backoff exponencial para los errores 500

### Consejos de rendimiento

Agrupa varios assets en una sola solicitud cuando sea posible

Valida los formatos de los assets del lado del cliente antes de enviarlos

Maneja el límite de solicitudes de forma adecuada

## Solución de problemas

### Problemas comunes

**Errores "INVALID_FORMAT":**

Asegúrate de que las URL incluyan el protocolo (`https://` o `http://`)

Verifica que los nombres de dominio no incluyan protocolos ni rutas

Comprueba que el formato de la dirección de blockchain coincida con el estándar EIP-155

**Errores "DUPLICATE_ASSETS":**

Quita las entradas duplicadas del arreglo de assets

Revisa si hay diferencias de mayúsculas y minúsculas

Verifica la normalización de las URL (barras finales, etc.)

**Errores "DOMAIN_NOT_ALLOWED":**

El dominio está en la lista de ignorados de ChainPatrol

Escribe a disputes@chainpatrol.io para disputar esta decisión

Considera reportar URL específicas en lugar del dominio completo

**Errores "ASSET_ALREADY_CORRECT":**

El asset ya tiene el estado que estás solicitando

Revisa el estado actual del asset antes de reportarlo

No hace falta ninguna acción: el asset ya está en el estado deseado

### Límite de solicitudes

El endpoint aplica un límite de solicitudes para prevenir abusos. Si recibes errores de límite de solicitudes:

Implementa backoff exponencial en tu lógica de reintentos

Considera agrupar solicitudes para reducir las llamadas a la API

Contacta a soporte si necesitas límites de solicitudes más altos

## Notas

La forma del payload de error es estable en todos los errores 422; revisa `data.errors` para ver los detalles por asset

Proporciona el `organizationSlug` y `assets` válidos para minimizar los errores 500 causados por un estado inválido

Todos los assets deben ser válidos para que se cree el reporte

Solo se puede crear un reporte una vez por dirección de correo electrónico para un asset específico

Si tienes problemas técnicos o preguntas sobre las respuestas de error, escribe a support@chainpatrol.io e incluye la respuesta de error completa en tu solicitud.
