## Descripción general

Registra la decisión de tu organización sobre una **Proposal** (propuesta para bloquear o permitir un asset) que está esperando por ti: una que ChainPatrol te escaló o una de un reporte que tú mismo enviaste. Son exactamente las Proposals que muestra tu página **Review** (revisión de propuestas pendientes de aprobación) y las que cuenta [`GET /organization/reports?needsCustomerReview=true`](/es/external-api/organization-reports-list), así que este endpoint te permite vaciar esa cola sin abrir la app web.

Hay un solo endpoint para los tres resultados posibles, que se distinguen por `decision`:

| Decisión | Qué hace | También se requiere |
| --- | --- | --- |
| `APPROVE` | Bloquea el **Asset** (activo digital: URL, dirección, perfil, app, etc.) | `label` (más `brandId` en las etiquetas que nombran un objetivo específico) |
| `REJECT` | Rechaza la Proposal | `rejectReason` |
| `WATCHLIST` | Rechaza la Proposal **y** deja el asset en la **Watchlist** (lista de seguimiento de assets sospechosos que se siguen monitoreando) para que se vuelva a evaluar si vuelve a estar activo | `watchlistReason` (más `note` cuando el motivo es `OTHER`) |

`WATCHLIST` es una variante del rechazo y no un resultado aparte: se guarda como una revisión `REJECT` con el asset agregado a la Watchlist, que es la misma escritura que hace la página Review. Por eso una respuesta exitosa de Watchlist vuelve con `review.decision: "REJECT"` y `watchlisted: true`.

<Warning>
  Una revisión no se puede deshacer a través de la API. `APPROVE` bloquea el asset y, como los assets son únicos por tipo y contenido, ese estado es global y no se limita a tu organización. Lee la Proposal antes de actuar sobre ella y usa el [límite de revisiones](#límite-de-revisiones) como un resguardo, no como una meta.
</Warning>

## Inicio rápido

### Autenticación

Incluye tu clave de API en el encabezado `X-API-KEY`:

```bash
X-API-KEY: your_api_key_here
```

### Cómo encontrar una Proposal para revisar

Los dos ID que necesita este endpoint salen del listado de reportes. Pide las Proposals que están esperando por ti y luego lee `proposals[].id` y `proposals[].asset.id`:

```bash cURL
curl -X GET 'https://app.chainpatrol.io/api/v2/organization/reports?needsCustomerReview=true&limit=10' \
  -H 'X-API-KEY: YOUR_API_KEY_HERE'
```

## Cuerpo de la solicitud

| Campo | Tipo | Obligatorio | Descripción |
| --- | --- | --- | --- |
| assetId | number | Sí | El asset al que apunta esta Proposal, tomado de `proposals[].asset.id`. Debe coincidir con el asset actual de la Proposal o la solicitud devuelve `409`. |
| decision | string | Sí | `APPROVE`, `REJECT` o `WATCHLIST`. |
| slug | string | No | Slug de la organización. Opcional para las claves de API con alcance de organización; obligatorio cuando tus credenciales tienen acceso a más de una organización. |
| label | string | Al aprobar | Por qué se bloquea el asset. Consulta [Etiquetas de bloqueo](#etiquetas-de-bloqueo). |
| brandId | number | Condicional | Marca que el asset suplanta. Obligatorio para `Brand Impersonation` y `Employee Impersonation`. Lista las tuyas con [`GET /organization/brands`](/es/external-api/organization-brands). |
| rejectReason | string | Al rechazar | `irrelevant`, `no_malicious_activity`, `insufficient_evidence`, `not_targeting_org` o `decayed`. |
| watchlistReason | string | Al enviar a la Watchlist | `DEAD`, `PARKING`, `NOT_ENOUGH_EVIDENCE` u `OTHER`. |
| note | string | Condicional | Detalle en texto libre. Obligatorio cuando `watchlistReason` es `OTHER`, ya que en ese caso la nota contiene el motivo. |

`proposalId` es un parámetro de ruta, así que no se repite en el cuerpo.

### Por qué assetId es obligatorio

`assetId` es un valor de confirmación, no una búsqueda. El servidor lo compara con el asset actual de la Proposal y devuelve `409` si no coinciden, lo que significa que un `proposalId` desactualizado o mal escrito falla de forma visible en lugar de revisar un asset distinto del que leíste. Toma ambos valores de la misma respuesta del listado y pásalos juntos.

### Etiquetas de bloqueo

`label` es obligatorio al aprobar y se ignora en los demás casos. `Brand Impersonation` y `Employee Impersonation` también requieren `brandId`.

| Etiqueta | Úsala cuando |
| --- | --- |
| `Brand Impersonation` | El asset usa directamente el nombre, el logo u otras marcas registradas de la marca |
| `Employee Impersonation` | El asset suplanta a un empleado específico de la organización |
| `Fake Employee` | El asset afirma trabajar en la empresa sin suplantar a una persona específica |
| `Targeting Org Users` | Una estafa que quieres dar de baja y que queda fuera de la suplantación directa |
| `General Phishing` | El asset intenta robar fondos de los usuarios |
| `C2 Server` | Servidor de comando y control que provee la infraestructura de backend para el phishing |
| `False Positive` | El asset se marcó por error y debería permitirse |

### Motivos de rechazo

Los motivos de rechazo alimentan el desglose que ChainPatrol usa para ajustar la detección, así que elige el más cercano en lugar de poner el motivo real en `note`:

| Motivo | Significado |
| --- | --- |
| `irrelevant` | No está relacionado con tu organización |
| `no_malicious_activity` | Es un asset real y no tiene nada malicioso |
| `insufficient_evidence` | No hay señales suficientes para actuar |
| `not_targeting_org` | Es malicioso, pero no apunta a tu organización |
| `decayed` | Ya no está activo o ya no es relevante |

## Respuesta

### Respuesta exitosa

```json
{
  "proposal": {
    "id": 4321,
    "reviewStatus": "APPROVED",
    "asset": {
      "id": 987,
      "type": "URL",
      "content": "https://scam-site.com",
      "status": "BLOCKED"
    }
  },
  "review": {
    "id": 55123,
    "decision": "APPROVE",
    "label": "General Phishing",
    "brandId": null,
    "comment": "General Phishing",
    "createdAt": "2026-08-06T10:30:00.000Z"
  },
  "watchlisted": false
}
```

### Respuesta de Watchlist

Una solicitud de Watchlist se registra como un rechazo con el asset en la Watchlist:

```json
{
  "proposal": {
    "id": 4321,
    "reviewStatus": "REJECTED",
    "asset": {
      "id": 987,
      "type": "URL",
      "content": "https://parked-domain.com",
      "status": "UNKNOWN"
    }
  },
  "review": {
    "id": 55124,
    "decision": "REJECT",
    "label": "",
    "brandId": null,
    "comment": "Add to watchlist: Parking page",
    "createdAt": "2026-08-06T10:32:00.000Z"
  },
  "watchlisted": true
}
```

### Campos de la respuesta

| Campo | Tipo | Descripción |
| --- | --- | --- |
| proposal.id | number | La Proposal revisada |
| proposal.reviewStatus | string | `APPROVED` o `REJECTED` después de tu decisión |
| proposal.asset | object | El asset, con su `status` después de tu decisión |
| review.id | number | La revisión que se creó |
| review.decision | string | Tal como quedó registrada en ChainPatrol. Una solicitud `WATCHLIST` se guarda como `REJECT`. |
| review.label | string | Etiqueta de bloqueo registrada en la revisión; vacía cuando no hay ninguna |
| review.brandId | number \| null | Marca registrada en la revisión |
| review.comment | string | El comentario compuesto, armado a partir de tu motivo y tu nota |
| review.createdAt | string | Marca de tiempo ISO 8601 de la revisión |
| watchlisted | boolean | Indica si el asset quedó en la Watchlist |

## Controles de seguridad

Aprobar a través de la API está sujeto a los mismos controles que la página Review y, a diferencia de la interfaz, **no se pueden anular**:

- **Reglas de legitimidad.** Si alguna regla de legitimidad habilitada concluyó que el asset parece legítimo (un dominio incluido en la lista Tranco, una coincidencia de regex con un dominio que te pertenece), la aprobación devuelve `403`. Esa decisión la tiene que tomar una persona en la página Review.
- **Assets en la Allowlist (lista de permitidos).** Un asset que actualmente está `ALLOWED` no se puede bloquear aquí; también devuelve `403`.

Ambos son callejones sin salida deliberados y no advertencias. Cuando te encuentres con uno, revisa la Proposal en la app.

### Límite de revisiones

Las revisiones están limitadas a **10 por organización por cada período móvil de 24 horas**. El cupo se comparte entre todas las credenciales de API que tiene tu organización, y las revisiones hechas desde la página Review no cuentan para ese cupo. Si lo superas, se devuelve `429`.

El límite existe porque una revisión no se puede deshacer y es fácil recorrer una cola en bucle por accidente. Trátalo como un resguardo: si lo alcanzas con frecuencia, conviene vaciar la cola en la app.

## Respuestas de error

### 400 Bad Request

No se cumplió un requisito condicional, o el tipo de asset no se puede enviar a la Watchlist:

```json
{
  "message": "`label` is required when approving a proposal",
  "code": "BAD_REQUEST"
}
```

### 403 Forbidden

La credencial no corresponde a un miembro de la organización con rol de cliente, o un control de seguridad rechazó la escritura:

```json
{
  "message": "This asset cannot be approved over the API because an enabled legitimacy rule marks it as legitimate. Review it on the Review page.",
  "code": "FORBIDDEN"
}
```

### 404 Not Found

La Proposal no existe o no es una de las tuyas:

```json
{
  "message": "Proposal not found",
  "code": "NOT_FOUND"
}
```

### 409 Conflict

`assetId` no coincide con el asset actual de la Proposal, o la Proposal ya fue resuelta:

```json
{
  "message": "assetId does not match the proposal's asset",
  "code": "CONFLICT"
}
```

### 429 Too Many Requests

Se agotó el cupo diario de revisiones de la organización:

```json
{
  "message": "This organization has reached its limit of 10 proposal reviews per day over the API. Reviews from the Review page are not affected, and the limit resets within 24 hours.",
  "code": "TOO_MANY_REQUESTS"
}
```

## Casos de uso

### Vaciar la cola que está esperando por ti

Lee las Proposals que están esperando por tu organización y luego actúa sobre cada una:

<CodeGroup>

```typescript TypeScript
const listed = await fetch(
  "https://app.chainpatrol.io/api/v2/organization/reports?needsCustomerReview=true&limit=20",
  { headers: { "X-API-KEY": process.env.CHAINPATROL_API_KEY! } }
).then((res) => res.json());

reviewQueue: for (const report of listed.reports) {
  for (const proposal of report.proposals) {
    // Decide from the asset and its scan data before writing anything.
    const decision = shouldBlock(proposal.asset)
      ? { decision: "APPROVE", label: "General Phishing" }
      : { decision: "REJECT", rejectReason: "no_malicious_activity" };

    const res = await fetch(
      `https://app.chainpatrol.io/api/v2/organization/proposals/${proposal.id}/review`,
      {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
          "X-API-KEY": process.env.CHAINPATROL_API_KEY!,
        },
        body: JSON.stringify({ assetId: proposal.asset.id, ...decision }),
      }
    );

    if (res.status === 429) {
      console.log("Daily review budget spent — finish the rest in the app.");
      break reviewQueue;
    }
    if (res.status === 403) {
      console.log(`Proposal ${proposal.id} needs a person on the Review page.`);
      continue;
    }
  }
}
```

```python Python
import os
import requests

headers = {
    "Content-Type": "application/json",
    "X-API-KEY": os.environ["CHAINPATROL_API_KEY"],
}

listed = requests.get(
    "https://app.chainpatrol.io/api/v2/organization/reports",
    headers=headers,
    params={"needsCustomerReview": "true", "limit": 20},
).json()

def review_queue():
    for report in listed["reports"]:
        for proposal in report["proposals"]:
            # Decide from the asset and its scan data before writing anything.
            decision = (
                {"decision": "APPROVE", "label": "General Phishing"}
                if should_block(proposal["asset"])
                else {"decision": "REJECT", "rejectReason": "no_malicious_activity"}
            )

            res = requests.post(
                f"https://app.chainpatrol.io/api/v2/organization/proposals/{proposal['id']}/review",
                headers=headers,
                json={"assetId": proposal["asset"]["id"], **decision},
            )

            if res.status_code == 429:
                print("Daily review budget spent — finish the rest in the app.")
                return
            if res.status_code == 403:
                print(f"Proposal {proposal['id']} needs a person on the Review page.")
                continue

review_queue()
```

### Dejar en la Watchlist un asset que quedó inactivo

Un asset que está inactivo o estacionado (con una página de parking) no es un falso positivo: envíalo a la Watchlist para que ChainPatrol lo vuelva a evaluar si vuelve a estar activo:

```bash cURL
curl -X POST 'https://app.chainpatrol.io/api/v2/organization/proposals/4321/review' \
  -H 'Content-Type: application/json' \
  -H 'X-API-KEY: YOUR_API_KEY_HERE' \
  -d '{
    "assetId": 987,
    "decision": "WATCHLIST",
    "watchlistReason": "OTHER",
    "note": "Registrar suspended the domain; watch in case it is restored"
  }'
```

## Desde la CLI

La [ChainPatrol CLI](/es/cli/overview) envuelve este endpoint y pide confirmación antes de escribir:

```bash
chainpatrol reports list --org acme --needs-customer-review --json
chainpatrol proposals review 4321 --asset-id 987 --decision approve --label "General Phishing"
```

Pasa `--yes` para omitir la confirmación en un script, o `--dry-run` para imprimir el payload sin enviarlo. Consulta [`proposals review`](/es/cli/commands/proposals) para ver todas las opciones.

## Buenas prácticas

### Lee antes de escribir

Cada solicitud necesita el `assetId` de un listado que acabas de leer, y eso es deliberado. Obtén la Proposal, decide a partir de su asset y de los datos de su escaneo, y solo entonces revísala: no inventes ID ni reutilices un listado viejo.

### Trata el 403 como una derivación, no como una falla

Un `403` de un control de seguridad significa que la decisión necesita a una persona, no que tu integración esté rota. Registra el ID de la Proposal y sigue adelante; no reintentes.

### No reintentes un 409

Un `409` significa que el asset no coincide o que la Proposal ya está resuelta. Vuelve a leer la Proposal en lugar de reintentar con el mismo cuerpo.

## Notas

- Las revisiones deben atribuirse a un miembro de la organización con rol de cliente. Las credenciales de staff se rechazan con `403`.
- El estado del asset es global: los assets son únicos por tipo y contenido, así que aprobar bloquea el asset en todas partes y no solo para tu organización.
- No todos los tipos de asset se pueden enviar a la Watchlist. Los tipos que la Watchlist no puede volver a verificar se rechazan con `400` en lugar de omitir en silencio el envío a la Watchlist.
- `GET /organization/reports` devuelve `proposals[].id` justamente para que las Proposals se puedan referenciar aquí.
