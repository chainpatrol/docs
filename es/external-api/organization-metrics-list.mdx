## Descripción general

Obtén las métricas de seguridad de tu organización, incluidos reportes, amenazas bloqueadas, **Takedowns** (solicitudes de baja de contenido fraudulento) y más. Este endpoint ofrece analíticas completas sobre la postura de seguridad de tu organización. La organización se infiere automáticamente a partir de tu clave de API.

## Inicio rápido

### Autenticación

Incluye tu clave de API en el encabezado `X-API-KEY`:

```bash
X-API-KEY: your_api_key_here
```

## Parámetros de consulta

| Parámetro | Tipo   | Obligatorio | Descripción                                                |
| --------- | ------ | ----------- | ---------------------------------------------------------- |
| brandSlug | string | No          | Filtra las métricas por una marca específica. Requiere el feature flag brands-metrics.                  |
| startDate | string | No          | Fecha de inicio de las métricas (formato ISO 8601). Si no se indica, se toma por defecto el inicio de los tiempos. |
| endDate   | string | No          | Fecha de fin de las métricas (formato ISO 8601). Si no se indica, se toma por defecto la fecha actual.        |

| metrics.threatsWatchlisted     | number | Cantidad de amenazas agregadas a la **Watchlist** (lista de seguimiento de assets sospechosos que se siguen monitoreando); 0 en las consultas filtradas por marca |

| metrics.takedownsCompleted     | number | Cantidad total de takedowns completados con éxito          |

## Tipos de métricas

### Métricas a nivel de organización (por defecto)

Cuando no se indica `brandSlug`, devuelve las métricas de toda la organización:
- Agrega todas las **Proposals** (propuestas para bloquear o permitir un asset), los reportes y los takedowns de la organización
- Incluye las amenazas con estado `BLOCKED`, `APPROVED` y `AUTO_APPROVED`
- El filtro por fecha se aplica a las marcas de tiempo `createdAt`
- Incluye todas las marcas de la organización

### Métricas a nivel de marca (opcional)

Cuando se indica `brandSlug` (requiere el feature flag brands-metrics):
- Filtra las métricas a una marca específica mediante el historial de revisión
- Consulta el historial de estados de los assets para encontrar las amenazas bloqueadas específicas de la marca
- Usa la tabla de historial de estados con las revisiones de marca
- El filtro por fecha de los takedowns usa las marcas de tiempo `updatedAt`
- **Nota:** `threatsWatchlisted` siempre devuelve 0 en las consultas acotadas a una marca

## Casos de uso

### Obtener las métricas de todo el historial

Obtén las métricas de todo el historial de tu organización:

```typescript
const response = await fetch(
  "https://app.chainpatrol.io/api/v2/organization/metrics",
  {
    headers: { "X-API-KEY": "YOUR_API_KEY_HERE" },
  }
);

const { metrics, blockedByType, blockedByDay } = await response.json();
console.log(`Total new threats: ${metrics.newThreats}`);
console.log(`Blocked by type:`, blockedByType);
```

### Obtener las métricas de una marca específica

Obtén las métricas filtradas a una marca específica:

```typescript
const response = await fetch(
  "https://app.chainpatrol.io/api/v2/organization/metrics?brandSlug=my-brand",
  {
    headers: { "X-API-KEY": "YOUR_API_KEY_HERE" },
  }
);

const { metrics } = await response.json();
console.log(`Brand threats blocked: ${metrics.newThreats}`);
```

### Obtener las métricas mensuales

```typescript
async function getMonthlyMetrics(year: number, month: number) {
  const startDate = new Date(year, month - 1, 1);
  const endDate = new Date(year, month, 0, 23, 59, 59);

  const response = await fetch(
    `https://app.chainpatrol.io/api/v2/organization/metrics?startDate=${startDate.toISOString()}&endDate=${endDate.toISOString()}`,

  const { metrics } = await response.json();
  return metrics;
}

// Get metrics for January 2024

```

### Comparar períodos de tiempo

```typescript
async function compareMetrics(period1Start: string, period1End: string, period2Start: string, period2End: string) {
  const [period1Response, period2Response] = await Promise.all([
    fetch(
      `https://app.chainpatrol.io/api/v2/organization/metrics?startDate=${period1Start}&endDate=${period1End}`,
      { headers: { "X-API-KEY": "YOUR_API_KEY_HERE" } }
    ),
    fetch(
      `https://app.chainpatrol.io/api/v2/organization/metrics?startDate=${period2Start}&endDate=${period2End}`,
      { headers: { "X-API-KEY": "YOUR_API_KEY_HERE" } }
    ),
  ]);

  const period1 = await period1Response.json();
  const period2 = await period2Response.json();

  const change = {
    reports: period2.metrics.reports - period1.metrics.reports,
    newThreats: period2.metrics.newThreats - period1.metrics.newThreats,
    takedownsCompleted: period2.metrics.takedownsCompleted - period1.metrics.takedownsCompleted,
  };

  console.log("Period-over-period change:", change);
  return change;
}
```

### Analizar la distribución de amenazas

```typescript
async function analyzeThreats() {
  const response = await fetch(
    "https://app.chainpatrol.io/api/v2/organization/metrics",
    {
      headers: { "X-API-KEY": "YOUR_API_KEY_HERE" },
    }
  );

  const { metrics, blockedByType } = await response.json();

  // Calculate percentages by asset type
  const total = metrics.newThreats;
  const distribution = blockedByType.map((item) => ({
    type: item.type,
    count: item.count,
    percentage: ((item.count / total) * 100).toFixed(2),
  }));

  console.log("Threat distribution:", distribution);
  return distribution;
}
```

### Generar un panel de seguridad

```typescript
async function generateDashboard(days: number = 30) {
  const endDate = new Date();
  const startDate = new Date();
  startDate.setDate(startDate.getDate() - days);

  const response = await fetch(
    `https://app.chainpatrol.io/api/v2/organization/metrics?startDate=${startDate.toISOString()}&endDate=${endDate.toISOString()}`,
    {
      headers: { "X-API-KEY": "YOUR_API_KEY_HERE" },
    }
  );

  const { metrics, blockedByType } = await response.json();

  const dashboard = {
    period: `Last ${days} days`,
    summary: {
      totalReports: metrics.reports,
      newThreats: metrics.newThreats,
      threatsWatchlisted: metrics.threatsWatchlisted,
      takedownSuccessRate: 
        metrics.takedownsFiled > 0
          ? ((metrics.takedownsCompleted / metrics.takedownsFiled) * 100).toFixed(1) + "%"
          : "N/A",
      breakdown: {
        domains: metrics.domainThreats,
        twitter: metrics.twitterThreats,
        telegram: metrics.telegramThreats,
        other: metrics.otherThreats,
      }
    },
    topThreats: blockedByType
      .sort((a, b) => b.count - a.count)
      .slice(0, 3),
  };

  return dashboard;
}

// Usage
const dashboard = await generateDashboard(30);
console.log("Security Dashboard:", dashboard);
```

## Respuestas de error

### 401 Unauthorized

Se devuelve cuando la clave de API falta, no es válida o no tiene acceso a la organización:

```json
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "API key with organization access required"
  }
}
```

### 400 Bad Request

Se devuelve cuando los parámetros de consulta no son válidos:

```json
{
  "error": {
    "code": "BAD_REQUEST",
    "message": "Invalid date format. Use ISO 8601 format."
  }
}
```

### 404 Not Found

Se devuelve cuando el slug de la marca no se encuentra o no pertenece a tu organización:

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Brand not found"
  }
}
```

## Buenas prácticas

### Rangos de fechas
- Usa siempre el formato ISO 8601 para las fechas: `YYYY-MM-DDTHH:mm:ss.sssZ`
- Incluye la información de zona horaria (normalmente UTC con el sufijo `Z`)
- Omite ambas fechas para obtener las métricas de todo el historial
- Usa rangos de fechas coherentes al comparar períodos

### Rendimiento
- Guarda en caché los datos de métricas con un TTL adecuado (p. ej., 1 hora para paneles)
- Usa los filtros de fecha para consultar períodos específicos en lugar de filtrar del lado del cliente
- Considera programar instantáneas periódicas de las métricas para llevar un seguimiento histórico

### Análisis
- Compara las métricas de distintos períodos para identificar tendencias
- Monitorea la tasa de éxito de los takedowns para evaluar la efectividad de las acciones contra amenazas
- Haz seguimiento de las amenazas por tipo de asset para entender los patrones de ataque

## Notas

- La organización se determina automáticamente a partir de tu clave de API
- Todas las marcas de tiempo están en formato ISO 8601 con zona horaria UTC
- Si no se indica un rango de fechas, se devuelven las métricas de todo el historial
- Las métricas se calculan en tiempo real según el rango de fechas indicado
- El array `blockedByType` incluye todos los tipos de asset que tienen amenazas bloqueadas
- El array `blockedByDay` ofrece datos de serie temporal para visualización
- El filtro por marca requiere el feature flag brands-metrics
- Todas las consultas excluyen los registros eliminados de forma lógica (soft delete)
- Los rangos de fechas son inclusivos
- En las consultas filtradas por marca, `threatsWatchlisted` siempre devuelve 0
- El filtro por fecha de los takedowns usa marcas de tiempo distintas en las consultas por marca y en las consultas por organización
