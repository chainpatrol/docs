## Quick Start

### Authentication

Include your API key in the `X-API-KEY` header:

```bash
X-API-KEY: <api-key>
```

## Overview

List the email domains, email addresses, and wallet addresses tracked by a brand that can
be searched for leaked credentials.

## Notes

- Both `slug` and `brandId` are required, including when using an organization-scoped API
  key. `brandId` is the brand's `id` from [List Organization
  Brands](/external-api/organization-brands). That endpoint requires an organization-scoped
  API key and returns brands for that key's organization.
- Organization-scoped API keys must match `slug`; staff user keys can name any organization.
  Sessions must belong to a `SUPERUSER`, `SUPPORT`, organization `OWNER`, or organization
  `ADMIN`. Dark Web Monitoring must be enabled for the organization.
- Targets are built from the brand's non-deleted `EMAIL` and `ADDRESS` assets. The brand's
  website URL does not create a domain target by itself.
- Each email asset adds its full address and its domain, except `gmail.com` is not listed as
  a domain. Individual Gmail addresses are included. A domain is marked as the default when
  it matches the host in the brand's `websiteUrl`.
- Address assets are stored as CAIP-2 values such as `eip155:1:0x…`; the target uses the raw
  address without that prefix. `0x` addresses are deduplicated case-insensitively; addresses
  on other chains are case-sensitive.
- Targets are ordered by domains (default first, then alphabetical), emails (alphabetical),
  then wallets (alphabetical). A brand without email or address assets returns no targets.
- Invalid `slug` or `brandId` (less than 1) returns `400`. Missing authentication returns
  `401` (`Authentication required. Provide API key or valid session.`).
- An unknown organization returns `404` (`Organization with slug '…' not found`); a brand
  outside the organization returns `404` (`Brand not found in organization`).
- An organization-scoped key must match `slug`; internal bot keys do not bypass this
  organization match. A mismatch returns `403` (`API key does not have access to
  organization '…'`). A session without the required role returns `403` (`Only organization
  owners, admins, or staff can run dark web searches`). If Dark Web Monitoring is disabled,
  the response is `403` (`Dark web monitoring is not enabled for this organization`).
