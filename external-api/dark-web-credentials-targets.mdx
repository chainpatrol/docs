---
title: List Dark Web Credential Targets
openapi: "GET /dark-web/credentials/targets"
---

List the email domains, email addresses, and wallet addresses tracked by a brand that can
be searched for leaked credentials.

## Authentication and access

Include your API key in the `X-API-KEY` header. Both `slug` and `brandId` are required,
including when you use an organization-scoped key.

The caller must have access to the organization and permission to search its dark web data:

- An organization-scoped API key must match `slug`. A staff user key can name any
  organization.
- A session must belong to a `SUPERUSER`, `SUPPORT`, organization `OWNER`, or organization
  `ADMIN`. Organization members without one of these roles cannot search.
- Dark Web Monitoring must be enabled for the organization.

To find a `brandId`, call [List Organization Brands](/external-api/organization-brands)
using an organization-scoped API key. The `id` of the brand is its `brandId`. That endpoint
lists brands for the key's organization and does not accept a `slug`; a staff user key
without organization access cannot use it.

## Request

```bash
curl --request GET \
  --url 'https://app.chainpatrol.io/api/v2/dark-web/credentials/targets?slug=your-org&brandId=232' \
  --header 'X-API-KEY: <api-key>'
```

| Query parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `slug` | `string` | Yes | Organization slug. |
| `brandId` | `integer` | Yes | Positive ID of a brand in the organization. |

Only non-deleted `EMAIL` and `ADDRESS` assets belonging to the brand are used to build the
options. The brand's website URL does not create a domain option by itself.

### Target rules and ordering

- Each email asset contributes its full address as an `email` option and its domain as a
  `domain` option. `gmail.com` is not listed as a domain, but individual Gmail addresses are
  included.
- A domain's `isDefault` is `true` when it matches the host in the brand's `websiteUrl`.
- Address assets are stored as CAIP-2 values such as `eip155:1:0x…`; the `crypto` option
  contains the raw address with that prefix removed. `0x` addresses are deduplicated
  case-insensitively; addresses on other chains are case-sensitive.
- Options are ordered by domains (default first, then alphabetical), email addresses
  (alphabetical), and wallets (alphabetical).
- A brand with no email or address assets returns an empty `options` array.

## Response

```json
{
  "options": [
    { "kind": "domain", "value": "example.com", "isDefault": true },
    { "kind": "email", "value": "security@example.com" },
    { "kind": "crypto", "value": "0xabc…" }
  ]
}
```

| Field | Type | Description |
| --- | --- | --- |
| `options` | `TargetOption[]` | Search targets available for the brand. |
| `options[].kind` | `"domain" \| "email" \| "crypto"` | Target type. |
| `options[].value` | `string` | Allowlisted domain, email address, or raw wallet address. |
| `options[].isDefault` | `boolean` | Included for domains; true when the domain matches the brand website host. |

## Errors

| Status | Message / cause |
| --- | --- |
| `400` | Empty `slug`, or `brandId` is less than 1. |
| `401` | `Authentication required. Provide API key or valid session.` |
| `403` | `API key does not have access to organization '…'`; `Only organization owners, admins, or staff can run dark web searches`; or `Dark web monitoring is not enabled for this organization`. |
| `404` | `Organization with slug '…' not found` or `Brand not found in organization`. |
